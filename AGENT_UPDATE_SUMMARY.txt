HOW CLIENT PCS GET THE UPDATE
-----------------------------
The published update is a "code" update (only agent/ replaced; node_modules unchanged). Shop PCs that already ran SETUP.bat poll agent_config.update_target_version every cycle. Admin triggers install via:
  - /admin Printer panel → "Install update" (super_admin only), or
  - npm run agent:push-update

The client agent downloads agent-1.0.1.3.zip from Supabase Storage (agent-updates bucket), verifies SHA256, stages it, registers a one-shot Windows Scheduled Task "SelfPrintUpdater", then exits. The task swaps files in place, restarts the agent, and waits for a health heartbeat. If the new version misses its heartbeat, it auto-rolls back to 1.0.1.2.

KNOWN CAVEAT
------------
Host-based/GDI drivers (e.g. Konica Minolta 205i) ignore per-document DEVMODE and rely on Set-PrintConfiguration rewriting the print queue. If Set-PrintConfiguration fails on a shop's driver, ALL files print with the queue's last duplex mode instead of per-file duplex. Check agent logs for "WARN: could not set queue duplex/paper mode". The agent's claim-time duplex-capability check is disabled because host-based drivers report canDuplex unreliably — a duplex job sent to a simplex-only printer will print single-sided without a print-time alert (only an informational warning in JobCard).
