## Findings addressed

**Fix 1** — `src/app/api/admin/jobs/[id]/convert/route.ts` and
`src/app/api/admin/jobs/[id]/route.ts` (PUT) now add
`(job.deliveryMethod === "delivery" ? job.deliveryFeePaise : 0)` on top of
`calculatePrice(...)` when re-deriving `pricePaise`.

**Fix 2 & 3** — `cleanupOldJobs` in `src/lib/db.ts` and `src/lib/db-supabase.ts`:
- excludes printed delivery jobs whose `delivery_status` is not `'delivered'`
  from the finished-job deletion set (cancelled/failed delivery jobs and
  delivered ones still clean up as before).
- adds `paid_at IS NULL` / `.is('paid_at', null)` to the expired
  `pending_payment` clause so paid-upfront orders are never expired.

**Fix 4** — Server: `src/app/api/jobs/route.ts` single-file POST now 400s with
`"Home delivery is not available for DOC/DOCX files — please upload a PDF"`
when `deliveryMethod === "delivery" && needsConversion`. Client:
`UploadForm.tsx` gates the delivery toggle render on a new `deliveryOfferable`
flag (`!isBulk && !isDocFile && onlinePaymentRailAvailable`) and a `useEffect`
forces `deliveryMethod` back to `"pickup"` (clearing contact fields) whenever
`deliveryOfferable` goes false. Note: in the current UI, selecting a
.doc/.docx file already redirects to a dedicated `docx-warning` step before
`file` state is ever populated, so this gate is unreachable through normal
flow today — implemented as instructed, as defense in depth.

**Fix 5** — `enterBulkMode` in `UploadForm.tsx` now resets `deliveryMethod` to
`"pickup"` and clears `customerName`/`customerPhone`/`deliveryAddress` on
entry. `goToPreview`'s delivery-validation guard is now `!isBulk && ...`.

**Fix 6** — Added `onlinePaymentRailAvailable` (checks
`pricing.shopUpiId`/`shopUpiQr`/`razorpayKeyId`) folded into the same
`deliveryOfferable` gate used for Fix 4/5, so the toggle is hidden whenever no
online payment rail is configured.

**Fix 7** — `AdminDashboard.tsx` SSE `job_update` merge now also carries
`deliveryStatus: data.deliveryStatus ?? j.deliveryStatus`. Confirmed the
delivery-status route already broadcasts `deliveryStatus` in its payload.

**Fix 8** — `src/app/api/admin/jobs/[id]/delivery-status/route.ts` uses
`await request.json().catch(() => null)` and returns 400 when the body is
null or `deliveryStatus` isn't one of the allowed values.

**Fix 9** — `scripts/tmp-test-pricing.ts` deleted.
